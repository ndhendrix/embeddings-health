# Activations toolkit — session handoff, 2026-08-25

Everything changed in one working session, why, and what is still unproven.

The starting point was Jacob's port (`olmoearth_activations/` plus scripts, then
uncommitted) and the two prototypes it replaced. The session got the pipeline
running end to end for eight locations, added ground-truth labelling and
correlation, and produced the first real result.

---

## 1. The result

Per-patch embeddings from **OlmoEarth-v1_2-Nano**, 256 px chips (2.56 km, 64×64
patches at 40 m), final layer (`blk4`), seven Maryland/DC locations, ~28,700
patches.

Probe R², **pooled out-of-fold** — a linear probe from all 128 dimensions to a
label, fit on every location but one and scored on the held-out one:

| Label | R² | Best dim | r |
|---|---|---|---|
| `built` (WorldCover impervious) | **+0.85** | 26 | −0.768 |
| `canopy` (WorldCover tree) | **+0.69** | 26 | +0.609 |
| `agriculture` | +0.54 | 3 | −0.393 |
| `grass` | +0.50 | 3 | −0.390 |
| `buildings` (OSM footprints) | +0.47 | 108 | +0.525 |
| `roads` (OSM) | +0.46 | 3 | +0.493 |
| `walkability` (OSM pedestrian ways) | +0.27 | — | — |
| `farmland` | +0.24 | 89 | +0.331 |
| `parking`, `park`, `recreation` | ≈ 0 | — | — |
| `healthcare` | −0.13 | — | — |

**Two things worth carrying forward.**

**Dim 26 is a single interpretable built↔vegetation axis.** It is the top
dimension for both `built` (r = −0.768) and `canopy` (r = +0.609), opposite
signs. One named coordinate.

**`healthcare` at −0.13 is a sampling limit, not a model limit.** Coverage is
~0.001; only `dc_medical` (0.065) has meaningful hospital area, five of seven
chips are essentially blank. Leave-one-location-out cannot work from one
informative location. The fix is to *sample at hospitals*
(`discover_locations.py --tag amenity=hospital`), not a better probe.

Caveat on the winners: pooled R² has the pooled mean as its baseline, so
between-location variance is in the denominator. A probe that only distinguishes
*which location* a patch came from scores well. For `built`/`canopy` the
within-chip structure is visible in the maps, so that is not the explanation.
For `farmland` (+0.24, concentrated almost entirely in `carroll_farmland`) it may
partly be.

All of this is exploratory. Neighbouring patches share ground, so the effective
sample is far below 28,700, and no p-values are reported.

## 2. New modules

| File | Purpose |
|---|---|
| `olmoearth_activations/locations.py` | Named-location registry, per-location scene dirs, scene-coverage lookup. PyYAML only — no torch |
| `olmoearth_activations/worldcover.py` | ESA WorldCover 10 m land cover: tile naming, range reads, class→coverage grids |

| `olmoearth_activations/osm_local.py` | Reads `.osm.pbf` extracts, returning Overpass-shaped elements so downstream code is shared |

## 3. New scripts

| Script | Purpose |
|---|---|
| `fetch_scene.py` | Sentinel-2 L2A via EODAG. Date range, cloud cap, target date. Reuses/symlinks an on-disk scene that covers the point. `--status`, `--check-mirrors` |
| `fetch_reference_data.py` | One command for WorldCover tiles + Geofabrik OSM extracts, with progress bars and generated READMEs |
| `fetch_labels.py` | Per-patch ground truth from two backends. 47 labels. Polygons filled, lines widened, points expanded to discs |
| `correlate_labels.py` | Per-dimension correlations + pooled out-of-fold linear probe per label |
| `discover_locations.py` | OSM tag → many named locations (e.g. every hospital in Maryland) |
| `notebooks/explore_activations.ipynb` | Generated by `build_explore_notebook.py`. Dimension maps, labelled scenes, correlation, parameterised label-vs-dimension comparison |

## 4. Changes to existing files

- **`encode.py`** — `_forward` no longer sends `fast_pass` together with
  `token_exit_cfg`; the encoder rejects that combination outright, so with the
  shipped defaults every tap except the deepest was guaranteed to fail.
- **`tiles.py`** — added `default_scene_dir()`, resolving to `<repo>/data/scenes`
  by walking up for `.git` rather than defaulting to the working directory.
- **`cli.py`** — `--location` on `encode-location`, supplying coordinate, scene
  directory and output label from one word. `--lat/--lon/--scene-dir/--name`
  still override.
- **`configs/default.yaml`** — `chip_px` 64→256, `depths` null→`[4]`, both with
  the reasoning recorded inline.
- **`pyproject.toml`** — `eodag>=4.0` and `pyogrio` as optional extras.
- **`.python-version`** (root and `embedding_generation`) — 3.12→3.11.

## 5. Bugs found and fixed

Grouped by where they lived. The recurring theme: **silent wrong answers**, not
crashes.

### Environment
1. **`uv sync` failed** — `.python-version` said 3.12, `pyproject.toml` required
   `>=3.11,<3.12`.
2. **A red herring I should flag.** `dlopen ... mmap failed errno=1` on torch,
   rasterio and pandas led me to diagnose Microsoft Defender blocking execution,
   and to suggest an IT ticket. **That was wrong** — it was a restriction on my
   own tooling's sandbox. The user's terminal worked fine. If similar symptoms
   recur, verify in a plain terminal before escalating.

### Scene handling
3. **`--scene-dir ~/scenes`** in the README put imagery outside the project. Now
   defaults to `<repo>/data/scenes`, which is gitignored (a scene is ~1 GB).
4. **Tile shadowing.** `T18SUH` was downloaded instead of `T18SUJ`; with both in
   one directory the band glob takes the alphabetically first match, so one
   scene *hides* the other rather than adding coverage. Fixed structurally with
   one directory per location, plus symlink reuse for locations sharing a tile
   (7 locations, 1.1 GB total instead of 7 GB).

### Model / encoder
5. **`fast_pass` + `token_exit_cfg` are mutually exclusive** — see above.
6. **Intermediate `token_exit` is broken upstream** in `olmoearth_pretrain`
   0.1.1: without `fast_pass` it mismatches token and mask shapes inside
   `project_and_aggregate` (256 vs 16). Worked around with `depths: [4]`.
   **`method: hooks` is the way to get middle layers** and works today.
7. **MPS lacks `aten::_upsample_bicubic2d_aa`** — needs
   `PYTORCH_ENABLE_MPS_FALLBACK=1`, or `device: cpu`.

### Statistics
8. **Mean-of-per-fold R² was unstable.** A label concentrated in one location
   leaves other folds with almost no target variance, so R² divides by nearly
   nothing: `farmland` produced one fold at −12 that swamped six others and read
   as "actively anti-predicted" rather than "too rare to measure". Replaced with
   one R² over pooled out-of-fold predictions. `farmland` went −12.1 → +0.24,
   `buildings` −0.09 → +0.47.
9. **`n_locations` was invisible.** `buildings` was scored from two locations
   (train-on-one, test-on-one) and displayed beside labels scored from seven.

### Labelling
10. **OSM land cover is sparse in rural America.** `carroll_farmland` returned
    25% of patches labelled versus 92% urban — the fields are real, nobody drew
    them. Any negative result there was about mapping, not the model. Fixed by
    taking land cover from **WorldCover** (wall-to-wall, 10 m) and leaving OSM
    for discrete built features.
11. **Node-mapped features were dropped.** Only ways and relations were
    requested, but most pharmacies, clinics and shops are single tagged points.
    `healthcare` and `food_retail` returned a confident zero. Fixed with
    `point_radius_px`, expanding a node to a disc.
12. **`line_width_px` was read and never applied** — roads rasterised one pixel
    wide regardless. Now dilated.
13. **Resume cached a bug.** A broken reader wrote zeros, and resume treated them
    as "already fetched" so the fix never ran. Zero-feature groups are now
    retried by default (`--keep-empty` opts out).
14. **Label-name collision across backends.** `canopy` meant OSM woodland and
    now means the WorldCover tree class. Reusing the cached array would have put
    two different measurements in one correlation column. Every label's source is
    now recorded and mismatches are discarded.
15. **`WorldCover-built` ≠ `OSM-buildings`** — the first is all impervious
    surface, the second roofs only (0.607 vs 0.171 on the same chip). Sources are
    now shown in all output.
16. **`WorldCover-farmland` is row crops only** — pasture and hay are class 30
    (`grass`). A dairy county read as 8% farmland while looking wholly
    agricultural. Added derived `agriculture` = classes 30 + 40.

### EODAG (all three were silent)
17. **`productType` → `collection`** in eodag 4.x. The old name is not rejected;
    it reports `Field required: collection` and then fails across all 15
    providers identically, reading like a credentials problem.
18. **`cloudCover` → `eo:cloud_cover`.** The wrong name fell through to a generic
    string *equality*, so the query asked for cloud cover exactly `"10.0"` and
    matched nothing. The correct key maps to a `le` comparison.
19. **`outputs_prefix` → `output_dir`.** Cannot be discovered by inspecting
    `download`'s signature — everything goes through `**kwargs`, so introspection
    reports it absent and picks the pre-3.0 name.
20. **`items_per_page` defaults to 20**, truncating ~35 products over three
    months.
21. **Impossible dates accepted.** `--end 2022-06-31` (June has 30 days) matched
    nothing, indistinguishable from a cloudy month. Now validated up front.
22. **`--target-date` silently did nothing** — the sensing-date lookup used
    property names 4.x dropped, returned `"?"`, and the sort saw every candidate
    as equally distant. Now tries STAC names and falls back to parsing the
    acquisition stamp from the product title.

### Overpass
23. Escalating failures — `429`, `504`, `500`, then `Connection refused` (a
    fair-use block, not a bug). Added retry with exponential backoff, three
    mirrors, `--check-mirrors`, bbox tiling for dense groups, and
    **response-body surfacing** (Overpass explains itself in the body, which was
    being discarded — the only thing distinguishing a busy server from a bad
    query).
24. **Local extracts** (`--osm-source local`) remove the dependency entirely and
    pin a dated snapshot, which is also better science than querying a live
    database.

### pyogrio
25. **`read_dataframe()` requires geopandas.** Switched to the raw reader plus
    shapely (already installed) rather than adding a large dependency chain.
26. **numpy `nan` is truthy.** After that switch, a missing tag arrived as `nan`
    and every feature read as tagged. Added a `_text()` coercion; 8/8 unit checks.

### My own shadowing bugs
27. `names` (locations) shadowed by `names` (WorldCover tiles) → progress read
    `[3/1]`.
28. `name` (location) shadowed by a `for name in empty:` loop → the figure looked
    for `walkability_chip.npz` instead of `westminster_chip.npz`.

## 8. Running the pipeline

```bash
cd code/activations

# imagery (only if no on-disk scene covers the point)
python scripts/fetch_scene.py --location <name> --start 2022-06-01 --end 2022-08-31 \
    --max-cloud 10 --target-date 2022-06-19

# encode
PYTORCH_ENABLE_MPS_FALLBACK=1 python scripts/encode_location.py \
    --location <name> --config configs/default.yaml --out artifacts/<name>

# label, entirely offline
python scripts/fetch_labels.py --location <name> --config configs/default.yaml \
    --osm-source local --cache-dir ../../data/worldcover

# correlate across every location, refreshed each time
python scripts/correlate_labels.py --all --top 8 --out artifacts/label_correlations.csv
```

Adding a location changes the leave-one-location-out folds, so **every** number
moves. Freeze the location set before quoting results.

## 9. Open questions

1. **Middle layers for SAEs.** `method: hooks` gives all four blocks today. Its
   pre-final-LayerNorm caveat breaks cross-depth comparison but is the
   conventional substrate for SAEs, one per layer.
2. **Sampling frame.** Landmark-centred (right for "does dim X encode
   hospitals") versus tract-stratified (right for anything touching PLACES).
   Different location sets.
3. **`add_location.py`** — the sketched one-command wrapper chaining
   scene → reference data → encode → label → correlate.
4. **Geofabrik region lookup** is hardcoded to MD/DC/VA.
5. **Scale.** At tens of locations `.SAFE` is fine. Beyond that, reading
   Sentinel-2 from STAC COGs would cut ~1 GB per location to ~5 MB and drop the
   Copernicus credential requirement — `TileSource` is already a Protocol, and
   `embedding_generation/composite.py` already talks to that catalog.
